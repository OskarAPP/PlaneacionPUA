INFORME 1: INICIACION Y PLANEACION
================================================================================

ORIGEN DEL PROYECTO Y PROBLEMA TECNICO A RESOLVER
--------------------------------------------------
- Necesidad institucional de digitalizar y centralizar la planeacion academica
  universitaria, eliminando procesos manuales basados en documentos fisicos o
  hojas de calculo desconectadas.
- Problema core: inexistencia de un sistema unificado para gestionar el ciclo
  completo del documento PUA (Planeacion Universitaria Academica), incluyendo
  asignacion de docentes, materias, competencias y generacion de versiones en PDF.
- Requerimiento de control de acceso por roles: administradores, docentes y
  personal administrativo deben operar sobre vistas y datos diferenciados.
- Necesidad de importacion masiva de bibliografia desde archivos CSV/Excel para
  reducir carga operativa del area academica.
- Requerimiento de trazabilidad de versiones de documentos PUA para auditoria
  y control de cambios.

REQUERIMIENTOS CORE
-------------------
- CRUD completo de entidades academicas: Facultades, Academias, Carreras,
  Materias, Docentes, Areas, Nucleos, Tipos de Materia, Cargos.
- Gestion de competencias genericas y especificas por carrera y facultad.
- Creacion, edicion y versionado de documentos PUA por modulos/secciones.
- Generacion y descarga de documentos PUA en formato PDF.
- Autenticacion de usuarios con roles diferenciados (Rol-Based Access Control).
- Importacion masiva de bibliografia via archivo CSV/Excel.
- Gestion de imagenes de perfil de docentes.
- Sistema de notificaciones interno.
- Despliegue en entorno Linux usando contenedores Docker.

ARQUITECTURA INICIAL PROPUESTA Y DECISIONES DE DISENO
------------------------------------------------------
- Arquitectura: API REST (backend) + SPA (Single Page Application, frontend).
  Separacion total entre capas de presentacion y logica de negocio.
- Backend expone una API RESTful en PHP con Laravel; el frontend la consume
  via fetch/axios desde React.
- Base de datos relacional normalizada (MySQL 8.0) con integridad referencial
  mediante claves foraneas.
- Versionado de documentos PUA modelado como entidad independiente (PuaVersion)
  vinculada a PuaDocumento, permitiendo historico completo por documento.
- Modularizacion del documento PUA en secciones (PuaModulo) identificadas por
  slug, facilitando guardado parcial e independiente.
- Almacenamiento de imagenes de perfil en base de datos (campo BLOB/referencia).
- Redis para cache y colas de trabajos asincrono (generacion de PDF pesado).
- Nginx como servidor web para el frontend en produccion; PHP-FPM para el backend.

ACCIONES OPERATIVAS CLAVE Y RESOLUCION DE BLOQUEOS
---------------------------------------------------
- Bloqueo: configuracion de CORS para permitir peticiones del frontend (localhost:5173)
  al backend (localhost:8000). Resolucion: configuracion de middleware CORS en Laravel.
- Bloqueo: migraciones no se ejecutaban automaticamente en Docker. Resolucion:
  script docker-entrypoint.sh ejecuta `php artisan migrate --force` al iniciar.
- Bloqueo: rutas SPA de React devuelven 404 en Nginx al recargar pagina directa.
  Resolucion: nginx.conf con directiva `try_files $uri $uri/ /index.html`.
- Accion clave: inclusion de dump SQL inicial (pua_oficial.sql) y seeders para
  facilitar replicacion del entorno con datos de prueba.
- Accion clave: configuracion de phpunit.xml con SQLite in-memory para tests
  rapidos sin dependencia de MySQL en CI local.
- Accion clave: documentacion de ejecucion en Linux (MANUAL_EJECUCION_DOCKER_VM_LINUX)
  para facilitar onboarding de nuevos desarrolladores y despliegue en produccion.

INFORME 3: DESARROLLO E IMPLEMENTACION
================================================================================

LOGICA PRINCIPAL E INTEGRACIONES CLAVE
---------------------------------------
API REST — Backend (Laravel):
  - 105+ endpoints REST organizados en routes/api.php.
  - Controladores con metodos estandar (index, store, show, update, destroy)
    mas metodos especializados (e.g., agregarFacultad, quitarCarrera,
    importar, generarPdf).
  - Relaciones Eloquent:
    * Docente hasMany Materias (via DocenteMateria pivot).
    * Docente belongsToMany Facultades y Carreras.
    * Materia belongsTo Carrera, Facultad, Area, Nucleo, TipoMateria, Academia.
    * PuaDocumento hasMany PuaModulo y PuaVersion.
    * CompetenciaEspecifica belongsTo Carrera y Facultad.
  - Generacion de PDF: DomPDF renderiza vistas Blade con los datos del
    PuaDocumento y sus modulos; el archivo resultante se almacena como
    PuaVersion con referencia al binario o ruta de archivo.
  - Importacion de bibliografia: PHPSpreadsheet parsea archivos CSV/XLSX
    subidos via multipart/form-data; cada fila se mapea a un modelo
    Bibliografia y se persiste en batch.
  - Gestion de imagenes: almacenamiento de imagenes de perfil referenciadas
    por acceso_id, accesibles via endpoint GET /api/perfil-imagen/{id_acceso}.

SPA Frontend (React):
  - App.jsx define el enrutamiento principal con React Router DOM.
  - Contexto de autenticacion propagado via React Context API (PuaContext
    y contextos de sesion de usuario).
  - Patron de paginas con formularios de registro separados de las listas
    (e.g., Docentes.jsx + RegistroDocentes.jsx).
  - ProcesarPua.jsx: componente principal del flujo PUA, orquesta la
    seleccion de materia, docente, modulos y generacion de versiones.
  - SidebarProcesarPua.jsx: navegacion lateral entre secciones del documento
    PUA durante el proceso de edicion.
  - Modales reutilizables para confirmacion de acciones criticas (eliminar,
    generar PDF).
  - TailwindCSS con configuracion personalizada (tailwind.config.js) para
    paleta de colores institucional.

Base de Datos:
  - 20+ tablas con relaciones definidas via claves foraneas.
  - Migraciones Laravel para control de esquema versionado.
  - Seeders para datos iniciales (roles, cargos, tipos de materia, nucleos).
  - Dump SQL (pua_oficial.sql) incluido para restauracion rapida del entorno.
  - Indices unicos compuestos en Materia (nombre, carrera_id), Academia
    (nombre, facultad_id), Carrera (nombre, facultad_id).

DESAFIOS TECNICOS Y SOLUCIONES IMPLEMENTADAS
---------------------------------------------
- Desafio: generacion de PDFs con layout complejo desde Laravel.
  Solucion: DomPDF con plantillas Blade estructuradas; estilos CSS inline
  para compatibilidad con el renderizador HTML-to-PDF.
- Desafio: relaciones muchos-a-muchos entre Docentes, Facultades, Carreras
  y Materias con datos adicionales en la tabla pivot.
  Solucion: modelo pivot DocenteMateria con columnas extra; uso de
  withPivot() y sync()/attach()/detach() en Eloquent.
- Desafio: importacion de bibliografia con validacion de duplicados y
  manejo de errores por fila.
  Solucion: PHPSpreadsheet con iteracion fila por fila, try-catch por
  registro y respuesta con conteo de exitosos/fallidos.
- Desafio: versionado de documentos PUA sin perder el historial de cambios.
  Solucion: cada generacion de PDF crea una nueva PuaVersion con timestamp
  y referencia al documento padre; PuaDocumento mantiene estado mutable.
- Desafio: autenticacion sin Sanctum/Passport en una API consumida por SPA.
  Solucion: endpoint de login retorna datos de usuario y rol; el frontend
  persiste la sesion en estado local (Context API).

PATRONES DE DISENO Y OPTIMIZACIONES
-------------------------------------
- MVC estricto en Laravel: modelos (logica de datos), controladores
  (logica HTTP), vistas Blade (solo para generacion de PDF).
- Repository-light pattern: logica de consultas compleja encapsulada en
  metodos de modelos Eloquent y scopes.
- Componentes React atomicos y reutilizables: modales, sidebars y formularios
  extraidos como componentes independientes en /Components.
- Lazy loading implicito via React Router (separacion de rutas por modulo).
- Cache Redis disponible para consultas frecuentes (catalogos de roles,
  cargos, tipos de materia), configurado pero pendiente de implementacion
  explicita en controladores.
- Nginx con compresion gzip y cache de assets estaticos (configurado en
  nginx.conf para el frontend en produccion).
- Multi-stage Docker build para el frontend: stage Node 20 para compilar
  con Vite, stage Nginx Alpine para servir; reduce tamano de imagen final.

-------------------------------------------------
Seguridad:
  - Autenticacion no usa tokens JWT ni Sanctum; la sesion se gestiona en
    el frontend sin invalidacion de sesion en el servidor (sin logout real).
  - Endpoints de API sin middleware de autenticacion verificado
    (ausencia de auth:sanctum o similar en routes/api.php).
  - Passwords almacenados como password_hash; no se confirma uso de bcrypt
    en todos los flujos de creacion de usuarios.

Testing:
  - Tests backend limitados a los archivos de ejemplo de Laravel (ExampleTest);
    sin tests unitarios ni de integracion para los controladores y modelos
    del negocio.
